# Lesson Plan — Week 6: AEAD and the CBC padding oracle

**02005104 · Cryptography and Network Security · Year 4 · Semester 2 AY2026 · Lecture**
**Contact time: 100 minutes.** Kind: LAB.
Lab/analysis: [`labs/week06-aead`](../../labs/week06-aead/README.md) · slides: `slides/week06.md`.

## Objectives and preparation

Recover a bounded plaintext sample with the CBC oracle and show the supplied GCM control has no padding-validity signal.

The runnable vulnerable target is CBC without a MAC; the supplied fixed target is GCM. Prepare dependencies beforehand; do not require implementing a complete new CBC+MAC service in this slot.

Images, dependencies and long readings are preparation; confirm the environment before class.
Students may consult the supplied helper after explaining the bounded manual checkpoint. Only
authorized local targets/test data are used. An unavailable environment is handled with a
prepared trace/code example and documented follow-up, not a fabricated successful result.

## In-class run sheet

| Minutes | Activity |
|---|---|
| 0–10 | Retrieval quiz/review (Week 1: baseline diagnostic); recall previously taught material. |
| 10–20 | Brief the mechanism, safety scope and expected evidence. |
| 20–35 | Compare malformed requests and identify the padding-valid versus invalid response. |
| 35–60 | Run the supplied recovery helper on the supplied local secret; derive one recovered byte by hand and document the oracle relation. |
| 60–80 | Repeat tamper tests against GCM; explain authenticated rejection and uniform failure handling. |
| 80–95 | Compare results/control, explain the mechanism and limits, receive feedback; begin the assigned form. |
| 95–100 | Save evidence and submit the in-class checkpoint. |

**Core artifact:** Oracle-dependent plaintext recovery and GCM rejection.
